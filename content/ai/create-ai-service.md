당시에는 언어 모델이 지금처럼 발전하지 않았고, 사내에서 직접 AI를 개발하려다 보니 시행착오가 많았었는데, 회고 겸 내용을 정리해보았다.

## AI 서비스 개발하기

전 회사의 메인 프로젝트는 AI를 활용하여 사용자에게 제공하는 컨텐츠를 자동으로 생성하는 것이었다.  
사용자의 입력값이나 개인화된 텍스트 기반의 결과물을 제공하는 서비스였는데, 기존에 보유한 전문가가 직접 작성한 데이터(컨텐츠)들을 AI에 학습시켜, 새로운 컨텐츠를 생성해내는 것이 목표였다.   
간단한 템플릿 기반 생성이 아니라, 해당 분야의 전문가가 작성한 듯한 결과물을 목표로 했다.

최초 프로젝트를 기획한 시점은 2022년 무렵으로, 고도화된 언어 모델이 대중적으로 사용되지도 않았고, ChatGPT가 세상에 나오기 전이었다.  
당연히 ‘AI API를 활용하자’ 같은 선택지가 없었으니, 자연스럽게 '필요한 AI 모델을 직접 개발한다'라는 지금 생각하면 다소 무모하게 느껴질 수도 있는 결정을 내렸다.

모든 리소스를 AI에 투자하고, 데이터 사이언티스트와 ML 엔지니어를 채용하는 동시에 OO대학교 연구소와 산학 협력까지 맺으며 모델 개발을 시작했다.  
기존 데이터와 현재 사용자들의 데이터, 피드백들을 활용하며 AI 모델의 성능을 개선해 나가며, 초기에는 분명 기대감과 열정이 있었다.

### 문제

모든 것을 직접 개발하려다 보니, 규모와 복잡성을 초반에는 제대로 예상하지 못하고 여러 문제점들이 발생하기 시작했다.  
가장 먼저 부딪혔던 장벽은 바로 AI 학습에 필요한 빅데이터를 제대로 확보하고 다루는 일이었다.  
사용자 맞춤형 AI를 위해서 서비스 전반의 사용자 로그와 이벤트를 수집해야 했는데, 
원시 데이터를 모아 정제하고 AI 학습에 적합한 형태로 변환하는 복잡한 데이터 파이프라인 구축에만 상당한 시간과 노력이 선행되어야 했다.  

데이터 기반을 어느 정도 마련한 후에도 어려움은 계속되었다.  
모델 개발 및 운영을 위한 복잡한 인프라 문제. ‘개인화’라는 모호한 목표. 무엇보다 한국어 모델 자체의 기술적 한계가 발목을 잡았다.  
수십, 수백만 건의 데이터를 학습시켰음에도, AI는 어색한 문장만 출력했다.

### 현실

이런 문제들로 1년쯤 고생하는 중, ChatGPT가 등장했다.
ChatGPT는 별다른 튜닝 없이도 한국어를 자연스럽게 생성하는 모습을 보여줬다.
연구소에서 전달받은 연구 결과나 사내에서 테스트한 결과를 종합해보니 자체 모델 개발보다는 고도화된 언어 모델 API를 활용하는 것이 훨씬 더 효과적이라는 결론이었다.
모든 리소스를 쏟아부어도 해결하지 못했던 문제들을 저렴하고 쉽게 처리하는 것을 보며, 굉장히 허탈했다.
