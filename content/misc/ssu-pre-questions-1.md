## 이영재

### 구현해 놓은 카카오 로그인이 제대로(일반적으로 사용하는 방식대로) 한 거 맞는지

카카오 로그인을 일반적으로 권장되는 OAuth 2.0 방식대로 잘 구현한 걸까요?

- 소셜 로그인 플로우
    1. 클라이언트에서 소셜 계정 로그인 요청
    2. 소셜 서버에서 인가 코드 발급
    3. 서버 측에서 인가 코드를 받아 액세스 토큰 교환
    4. 액세스 토큰으로 사용자 정보 조회
    5. 인증된 사용자 정보 기반으로 서비스 자체 세션/JWT 생성 후 로그인 처리 완결
- 문서 확인
    - [서비스 로그인 과정](https://developers.kakao.com/docs/latest/ko/kakaologin/common#login-seq)

### 애플 로그인 제대로 한 거 맞는지(구현했을 때) / 애플 로그인 구현하는 법(구현 못 했을 때)

(구현) 애플 로그인 기능을 정상적으로 구현한 게 맞을까요?
(미구현) 애플 로그인 기능을 구현하고자 하는데, 어떻게 구현해야 할지 조언해 주실 수 있을까요?

- 고려 사항
    - Private Key 자동 갱신 처리
    - IOS, Web 환경에서의 토큰 발급 및 검증
    - 작업 시, 소셜 로그인을 위한 토큰이나 Secret, 서비스 토큰 등 명칭 구분
    - [Apple로 로그인](https://developer.apple.com/kr/sign-in-with-apple/get-started/)

## 유성진

### 에브리타임 크롤링, 퀴즈 생성 구현 점검해 주실 수 있는지

(구현) 에브리타임 크롤러와 퀴즈 생성 기능을 구현했는데, 잘 설계되었는지 점검해 주실 수 있을까요?
(미구현) 에브리타임 사이트에서 데이터를 크롤링하여 퀴즈를 생성하는 로직을 어떻게 구현해야 하는지 궁금합니다.

- 크롤러 확인 사항
    - 크롤러 스케줄링(실행 주기) 관리 및 크롤링 데이터 저장소(파일/DB 등)를 어떻게 설계 및 관리하는지?
    - 크롤링한 데이터를 어떻게 변환이나 필터링해서 퀴즈 형태로 정제했는지?
    - 크롤링을 통한 정보통신망 침해 여부(법적 문제) 고려
- 퀴즈 생성 및 구성
    - 퀴즈 형태(출제 방식이나 문항 유형, 난이도 등)를 어떻게 설정했는지?
    - 사용자 응답(정오답)이나 피드백을 분석하거나 반영했는지?

### ERD 잘 설계하는 법, 구현 중에 수정하면서 해도 되는지

ERD를 잘 설계하는 방법에 대해 조언해 주실 수 있을까요? 구현 과정에서 불가피하게 테이블 구조를 수정해야 할 때, 어떤 점을 유의하면 좋을까요?

- 고려 사항
    - 기획 분석 및 요구사항 확인하여 주요 엔티티(테이블)와 관계성(1:N, N:M 등)을 명확하게 정의
    - 구현 중에 테이블 구조가 달라져야 한다면 당연히 수정은 가능하지만, 변경 시점과 이유를 공유(이력 관리, 문서화 및 커뮤니케이션)
    - 배포 이후라면, 기존 데이터와 호환성, 백업 및 복구나 롤백 계획, 모니터링

### 스마트 스터디 플래너라는 앱에 추가할 기능이나 아이디어가 있으신지

스마트 스터디 플래너 앱에 추가할 만한 기능이나 아이디어, 발전 방향이 있을까요?

- 기능
    - 유저 데이터 분석 및 통계
    - 적절한 동기 부여나 보상, 경쟁 시스템
    - AI 기반 추천 시스템(학습 루틴 및 휴식 시간)

## 이재준

### 사용자가 업로드한 파일 임시 저장해야 할 때 로컬(OS가 제공하는 임시 공간)을 이용하는 것이 좋은지, 서버에 임시 저장하는 것이 좋은지

파일 업로드 시, 로컬에 임시 저장하는 것과 서버에 임시 저장하는 것 중 어떤 방식이 더 좋을까요?

- 로컬 : 단일 서버에 빠르고 간단하게 설정하여 구성
- 서버 : 일관성이 보장되고 접근 제어나 백업이 용이

### 업로드한 파일의 개수와 용량 제한에 대한

개인당 파일 업로드 개수와 용량을 어떻게 제한할지, 기준을 어떻게 설정하면 좋을까요?

- 확인 사항
    - 사용량(일별/월별 파일 업로드량) 및 사용자 수 예측
    - 인프라(서버나 스토리지 요금) 고려
    - 서비스 목적(문서 관리 vs 이미지 업로드)에 따라서 결정

### 개발하다가 더 나은 방법 혹은 다른 방식이 생각나면 그때그때 공유하는 좋을지 정기 회의 시간을 가지고 공유하는 것이 좋은지 (api 포함)

개발 중에 새로운 아이디어가 떠오를 때마다 즉시 공유하는 편이 좋을지, 아니면 정기 회의 시간에 제안하는 편이 나을까요?

- 즉시 공유 : 실시간 반영 및 피드백으로 빠르게 개선 가능하지만, 잦은 변경으로 혼선 및 피로도 증가, 일정 조정 필요
- 정기 회의 : 평시에 정리한 아이디어를 검토 및 정리하여 공유, 의견 조율 가능하지만, 즉각적인 피드백은 어려움

### 텍스트 추출기 → 문제 생성기에서 텍스트를 리스트로 넘겨줄지, String 객체로 전달할지

텍스트 추출기에서 문제(퀴즈) 생성기로 데이터를 보낼 때, 리스트 형태로 나누어 전달할지 통째로 String을 넘길지, 어떤 방법이 나을까요?

- 구조나 후속 로직(문장 분석, 파싱 방안)에 따라
    - 문장 단위로 나누어 처리하는 경우, 리스트
    - 단순하게 한 덩어리(String)로 전달하여, 파싱이나 가볍게 처리하는 경우, String

### pdf / 이미지 구분 기준을 15글자로 해도 괜찮을지 (임의의 설정한 기준입니다.)

PDF와 이미지를 판별할 때, 단순히 텍스트 길이 15자 기준으로 나누는 방식이 적절할까요?

- 파일 헤더나 MIME 타입을 확인
